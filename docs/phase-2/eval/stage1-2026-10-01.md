## Recommendation and decisions

1. **Q1 — pass.** Keep bge-m3. The engine wins in every query category; the largest gains are on
   typos (0.96 vs 0.48), code-switched text (0.92 vs 0.54), transliteration (0.83 vs 0.45) and
   identifiers (0.77 vs 0.50).
2. **Weakest categories:** `symptom` (0.756) and `identifier` (0.774). Candidates for later tuning
   are the fusion weights and `T_TRGM`; both are kept at their A.8 values for now.
3. **Recall@1 is not better** (0.347 vs 0.359), although MRR and nDCG are. The engine finds the
   right item far more often, but does not always rank it first. Jev reranking (slice 13) targets
   exactly this.
4. **`T_FLOOR` 0.35 → 0.55.** The 0.35 placeholder never fires with bge-m3: unrelated text scores
   above it, so every no-match query returned 20 results. No floor separates real matches from noise
   cleanly. 0.55 is the knee: Recall@5 −1.1 points, no-match results 20 → 11 per query, and 0.5 % of
   real queries left with no result. The rest of the noise is Jev's job (slice 13, Q4).
5. **Q2 — re-measure on production hardware** before release. The production host currently has
   about 1.6 GB free (the Phase 1 api, worker and bot each load fastembed); bge-m3 needs about
   2.5–3 GB, so measure after slice 12 is deployed and fastembed is gone. Retrieval latency here is
   the harness's in-memory mirror; also time `GET /search` against the indexed Postgres.

Tests: the full backend suite passes with `T_FLOOR = 0.55` (804 tests). The fake embedding endpoint
has a lower cosine scale, so `tests/conftest.py` pins tests to 0.35.

## Runbook — how to reproduce

Prerequisites: the dataset directory, Docker, and this repo's dev stack (`make dev`) running, so the
`releasewatch-api-1` container has the slice-12 code mounted and the dev Postgres has `pg_trgm`.

```sh
# 1. Embedding servers on the dev compose network (arm64 host shown; on amd64 use :cpu-1.9.4).
#    Behind a host proxy, pass it in: -e HTTPS_PROXY=http://host.docker.internal:<port>
IMG=ghcr.io/huggingface/text-embeddings-inference:cpu-arm64-latest
docker volume create rw-eval-models
docker run -d --name rw-eval-bgem3 --network releasewatch_default -v rw-eval-models:/data \
  $IMG --model-id BAAI/bge-m3 --max-batch-tokens 2048
# wait for: docker exec releasewatch-api-1 python -c "import httpx;print(httpx.get('http://rw-eval-bgem3:80/health').status_code)"

# 2. Copy the dataset in (it holds production text — delete it afterwards).
docker cp ~/Projects/Personal/GitHub/releasewatch-eval-data/eval-dataset releasewatch-api-1:/tmp/eval-dataset

# 3. Score the engine.
docker exec releasewatch-api-1 sh -c 'cd /app && python -m scripts.search_eval stage1 \
  --phase engine --state /tmp/eval-state --dataset /tmp/eval-dataset --endpoint http://rw-eval-bgem3:80/v1'

# 4. Swap models (both don't fit in an 8 GB Docker VM), score the baseline.
docker rm -f rw-eval-bgem3
docker run -d --name rw-eval-minilm --network releasewatch_default -v rw-eval-models:/data \
  $IMG --model-id sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2 --max-batch-tokens 2048
docker exec releasewatch-api-1 sh -c 'cd /app && python -m scripts.search_eval stage1 \
  --phase baseline --state /tmp/eval-state --dataset /tmp/eval-dataset --baseline-endpoint http://rw-eval-minilm:80/v1'

# 5. Report, then clean up.
docker exec releasewatch-api-1 sh -c 'cd /app && python -m scripts.search_eval stage1 \
  --phase report --state /tmp/eval-state --dataset /tmp/eval-dataset --out /tmp/eval-state/stage1.md --host "<where it ran>"'
docker cp releasewatch-api-1:/tmp/eval-state/stage1.md .
docker rm -f rw-eval-minilm
docker exec releasewatch-api-1 rm -rf /tmp/eval-dataset /tmp/eval-state
```

With 16 GB or more for Docker, steps 3–5 collapse to one command without `--phase`
(`--endpoint … --baseline-endpoint …`).

### Problems met on this run, and fixes

| Symptom | Cause | Fix |
|---|---|---|
| TEI exits with "no matching manifest for linux/arm64" | the pinned `cpu-1.9.4` tag is amd64-only | use `cpu-arm64-latest` locally; record its digest |
| TEI can't download the model ("error sending request") | the host reaches the internet through a local proxy that containers don't inherit | `-e HTTPS_PROXY=http://host.docker.internal:<port>` (and `HTTP_PROXY`) |
| bge-m3 exits 137, `OOMKilled` while "Warming up model" | warm-up uses the full `--max-batch-tokens 16384` batch | `--max-batch-tokens 2048` (batching only; embeddings unchanged) |
| bge-m3 + MiniLM together OOM the Docker VM | bge-m3 alone uses ~5.4 GB; the dev worker/bot hold ~3 GB more | pause the dev `worker` and `bot`, score one model at a time (`--phase`), restart them after |
